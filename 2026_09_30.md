- ### Mini-case A: AI-phishing mot skoladministration
- Ett välskrivet mejl ser ut att komma från en betrodd intern avsändare och ber mottagaren att öppna en länk för att uppdatera ett konto. Det är inte fastställt om mejlet skapats med AI.
	- Vilka fakta finns och vilka antaganden görs?
		- Fakta:
			- Mejlet kommer från en intern address, mottagaren bes klicka på en länk, mejlet ser välskrivet ut
		- Antaganden:
			- Det är möjligt att det är ett phishing attempt men det har vi inte underlag för att bevisa, Om det är phishing kan vi anta att exploitern har tillgång till internt email, Vi kan anta att detta mejl har skickats till fler personer än mottagaren, Attackeraren kan ha tillgång till konton bundna till mejlet
	- Vilka tillgångar och CIA-dimensioner berörs?
		- Information från att inte klicka länken : Confidentiality, Mejl-systemet : Integrity, Förtroende för personen som skickade mejlet : Integrity, Avsändarens personliga information från deras mejl account : Cofidentiality, Avsändarens tillkomst till sitt mejl : Accessability, System som är direkt kopplade till mejlet så som github tex : Confidentiality + Integrity + Accessability
	- Vilka CIS Controls kan vara relevanta?
		- 1, 3, 4, 5, 6, 14, 17
	- Vilken förebyggande och vilken upptäckande åtgärd föreslår gruppen?
		- Kontakta mejl-konto ägaren i person om möjligt, kontrollera kontots handlingar i system kopplade till mejl-kontot, Säkra mejl system, Träna personal att inte klicka på suspicious länkar, Träna personal i lösenord- och kontoshantering, Jämför inkommande mejl med andra konton, Se om möjligt var inloggningen till mejl-konton kom ifrån och vilken tid
